# نظام إدارة تدقيق التشريعات الأردنية (الديوان · قسطاس)

تطبيق ويب عربي خفيف لإدارة التدقيق اليدوي للأنظمة بين **ديوان التشريع والرأي** و**قسطاس**.
مبني بـ HTML وCSS وJavaScript وPHP فقط، مع مكتبة PhpSpreadsheet. **لا توجد أي قاعدة بيانات.**

- ملف المطابقة (Excel) هو مصدر بيانات المطابقة الأصلية، ولا يُعدَّل إطلاقاً.
- نتائج التدقيق تُحفظ في ملف Excel: `data/reviews/reviews.xlsx` (ورقة «نتائج التدقيق»).
- عند التصدير يُنشأ ملف Excel جديد هو نسخة من الملف الأصلي بكل أوراقه وقيمه وصيغه، مضافاً إليه ورقة «نتائج التدقيق».
- حسابات المستخدمين في `data/users.json`، والإعدادات في `data/settings.json`.

---

## 1. متطلبات التثبيت

- PHP 8.1 أو أحدث، مع الإضافات: `zip`, `xml`, `xmlreader`, `xmlwriter`, `dom`, `mbstring`, `gd`, `fileinfo`, `iconv`.
- خادم ويب (Apache أو Nginx) أو خادم PHP المدمج للتجربة.
- مساحة قرص: نحو 1 جيجابايت للبيانات (ملفات المواد كبيرة: مواد الديوان ~350MB).
- ذاكرة PHP: 512MB للصفحات العادية، و2GB لعملية استيراد ملفات المواد (يُضبط تلقائياً داخل الكود عند الاستيراد).

## 2. تثبيت المكتبات

مجلد `vendor` مرفق جاهزاً (PhpSpreadsheet 5.x). لإعادة التثبيت من الإنترنت:

```bash
composer install
```

## 3. إعداد النظام

1. انسخ مجلد المشروع إلى الخادم.
2. اجعل **جذر الموقع (Document Root)** هو المجلد `public` فقط. مجلدات `src` و`data` و`tools` و`vendor` يجب ألا تكون متاحة عبر الويب.
   (إذا اضطررت لوضع المشروع كاملاً داخل مجلد الويب على Apache فملف `.htaccess` في الجذر يمنع الوصول إليها.)
3. امنح خادم الويب صلاحية الكتابة على المجلد `data`:
   ```bash
   chown -R www-data:www-data data && chmod -R 775 data
   ```
4. لرفع الملفات الكبيرة عبر المتصفح ارفع حدود PHP في `php.ini` (أو عبر `public/.htaccess` على Apache):
   ```ini
   upload_max_filesize = 512M
   post_max_size = 520M
   memory_limit = 2048M
   max_execution_time = 600
   ```
   إذا لم تستطع تعديل هذه الحدود، استخدم الاستيراد من مجلد `data/incoming` أو من سطر الأوامر (القسم 7).

## 4. تشغيل الموقع

للتجربة المحلية:

```bash
php -d memory_limit=2048M -d upload_max_filesize=512M -d post_max_size=520M -S 0.0.0.0:8080 -t public
```

ثم افتح: `http://localhost:8080`

## 5. إنشاء حساب المسؤول

عند فتح الموقع أول مرة تظهر صفحة **الإعداد الأول** لإنشاء حساب المسؤول (تظهر مرة واحدة فقط).
أو من سطر الأوامر:

```bash
php tools/create-admin.php admin "اسم المسؤول" "كلمة-مرور-قوية"
```

## 6. إضافة المتطوعين

من **إدارة النظام والملفات ← إدارة المتطوعين**: أدخل الاسم الظاهر واسم المستخدم (أحرف لاتينية) وكلمة مرور (8 أحرف على الأقل).
يمكن تعديل الاسم وإعادة تعيين كلمة المرور وتفعيل الحساب أو تعطيله، ومتابعة نشاط كل متطوع.

## 7. رفع الملفات

### ملف المطابقة الأساسي
**إدارة النظام ← إدارة الملفات ← ملف المطابقة الأساسي** (`Bylaws_Diwan_Qistas_Matching.xlsx`).
يُفحص الملف قبل اعتماده: يجب أن يحتوي أوراق «المتطابقة» و«الديوان فقط» و«قسطاس فقط». تُقبل النسخة العربية أو الإنجليزية لعناوين الأعمدة.
عند استبدال الملف تُحفظ نسخة احتياطية من القديم، ونتائج التدقيق لا تُحذف لأنها مرتبطة بمعرّفات ثابتة.

**المعرّف الثابت لكل سجل** (لا يُستخدم رقم الصف):
| الفئة | المعرّف |
|---|---|
| متطابق | `M-{الديوان: pmk_ID}` |
| الديوان فقط | `D-{الديوان: pmk_ID}` |
| قسطاس فقط | `Q-{قسطاس: المعرف}` |

### ملفات المواد التشريعية
| المصدر | الملف | الربط |
|---|---|---|
| الديوان | `reg_articles.csv` (أو ZIP يحتويه) — صف لكل مادة | العمود `Bylow_pmk_ID` = «الديوان: pmk_ID» |
| قسطاس | `Bylaws_16.json` (أو ZIP يحتويه) — سجل لكل نظام مع `Articles` | المعرّف من الرابط `/laws/info/{ID}/` = «قسطاس: المعرف» |

عند الاستيراد يُبنى فهرس سريع (ملف صغير لكل تشريع في `data/index`) ويُستبدل الفهرس القديم بشكل ذري.
يستغرق استيراد مواد الديوان نحو 30–60 ثانية.

**للملفات الكبيرة** (موصى به لملف الديوان):

```bash
php tools/import-workbook.php  /path/Bylaws_Diwan_Qistas_Matching.xlsx
php tools/import-articles.php diwan  /path/reg_articles.zip
php tools/import-articles.php qistas /path/Bylaws_16.zip
```

أو ضع الملف في `data/incoming/` ثم اختر «استيراد ملف كبير من مجلد data/incoming» من صفحة الإدارة.

## 8. سير العمل

1. **المتطوع** يفتح «بطاقات التشريعات»، يصفّي حسب الاسم/الرقم/السنة/الفئة/الحالة/المتطوع/الأولوية، ويضغط **ابدأ التدقيق** على أي تشريع غير محجوز. يُسجَّل اسمه ووقت البدء، ولا يستطيع غيره تعديل المراجعة.
2. في صفحة التفاصيل: معلومات التشريع، مقارنة بيانات المصدرين جنباً إلى جنب، **مقارنة المواد** (اختيار يدوي للمواد، بحث، التنقل، إظهار الأرقام الموجودة في مصدر دون الآخر، إبراز الكلمات المختلفة كأداة بصرية فقط، البحث اليدوي عن سجل آخر للمقارنة)، ثم نموذج التوثيق.
3. **حفظ كمسودة** في أي وقت، و**إرسال نتيجة التدقيق** عند الاكتمال.
4. **المسؤول** يعتمد النتيجة أو يعيدها للتصحيح أو يحيلها لبحث إضافي، ويمكنه تحرير الحجز أو إعادة التخصيص.

**قواعد الإرسال (من إجراءات العمل SOP):** تدقيق البيانات الأساسية مكتمل، تحديد نتيجة تدقيق المواد، قرار نهائي، طريقة بحث واحدة على الأقل، رابط دليل واحد على الأقل، وملاحظات. القرارات من نوع «غير موجود – مؤكد» لا تُقبل إلا بعد توثيق **جميع** طرق البحث الإلزامية مع نتائجها.

**نسبة الإنجاز** تُحتسب من 9 خطوات فعلية: البدء، البيانات الأساسية، طرق البحث، المواد، الأدلة، الملاحظات، القرار، الإرسال، الاعتماد.

**نطاق التدقيق:** افتراضياً التشريعات حتى سنة 1960 (شاملة)، وللأنظمة المعدِّلة تُعتمد سنة النظام الأصلي. يُعدَّل من **إدارة النظام ← إعدادات التدقيق**، وكذلك خيارات القرار النهائي وطرق البحث.

## 9. النسخ الاحتياطية وحماية البيانات

- كل عملية حفظ تتم تحت **قفل ملفات** حصري (يمنع الحفظ المتزامن)، ثم:
  نسخة احتياطية تلقائية ← كتابة ملف مؤقت ← **التحقق من قراءته** ← استبدال ذري.
- كل مراجعة لها **رقم نسخة**؛ إذا عُدّلت من نافذة أخرى يُرفض الحفظ ولا تُستبدل البيانات بصمت.
- إذا كان الملف مشغولاً تظهر رسالة «الملف مستخدم حالياً… أعد المحاولة»، ويبقى ما أدخله المتطوع في النموذج.
- النسخ الاحتياطية: `data/backups/reviews` (آخر 300 نسخة)، `data/backups/source` (ملفات المطابقة السابقة)، `data/backups/users`.
- سجل عمليات دائم: `data/logs/journal.jsonl`، وسجل الأخطاء: `data/logs/app.log`.
- الاستعادة: **إدارة النظام ← التصدير والنسخ الاحتياطية ← استعادة** (تُحفظ النسخة الحالية قبل الاستعادة).
- للنسخ الاحتياطي الكامل للنظام يكفي نسخ مجلد `data` بالكامل، مثلاً يومياً:
  ```bash
  tar czf backup_$(date +%F).tar.gz data/users.json data/settings.json data/reviews data/source/main.xlsx data/source/main_meta.json
  ```

## 10. تنزيل ملف Excel بعد تحديثه

**إدارة النظام ← التصدير والنسخ الاحتياطية ← إنشاء وتنزيل ملف Excel المحدَّث.**
الناتج: الملف الأصلي بجميع أوراقه (اقرأني، ملخص، المتطابقة، الديوان فقط، قسطاس فقط) دون أي تغيير، مع ورقة «نتائج التدقيق» تتضمن: المعرّف، الفئة، الحالة، المتطوع، التواريخ، نتائج البحث بالرقم والاسم والجريدة والمحتوى، طرق البحث، القرار النهائي، روابط الأدلة، الملاحظات، الاختلافات، حالة المواد، حالة الاعتماد، ملاحظات المسؤول، تاريخ الاعتماد، ونسبة الإنجاز.
يمكن أيضاً تنزيل ملف النتائج الخام `reviews.xlsx` أو ملف المطابقة الأصلي.

## 11. بنية المشروع

```
public/            صفحات الموقع (جذر الويب)
  index.php        لوحة التحكم
  cards.php        بطاقات التشريعات
  review.php       تفاصيل التدقيق
  admin.php        إدارة النظام والملفات
  api.php          استرجاع المواد والبحث (JSON)
  download.php     التنزيلات
  login.php / logout.php / setup.php
  assets/          CSS و JavaScript
src/               منطق التطبيق (تخزين، أقفال، Excel، مواد، مراجعات، تصدير)
tools/             أدوات سطر الأوامر
data/              البيانات (تُنشأ تلقائياً — لا تُتاح عبر الويب)
vendor/            PhpSpreadsheet
```

## ملاحظات مهمة

- النظام **لا ينفذ أي مطابقة تلقائية** ولا يصدر حكماً بالتكافؤ القانوني؛ «أقرب مرشح» يُعرض كما ورد في ملف المطابقة للاسترشاد فقط، وإبراز الفروق أداة بصرية.
- لا تُعتمد أي نتيجة إلا بموافقة المسؤول.
- المسؤول لا يبدأ مراجعات بنفسه (لفصل التدقيق عن الاعتماد)، ويمكنه إعادة تخصيص أي تشريع لمتطوع.
